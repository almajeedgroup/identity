# ADR-006 · Small in-house i18n layer

**Status:** Accepted (provisional) · **Date:** 2026-10-04 · **Specs:** F04

## Context
Four locales (en, kn, hi, ur), right-to-left Urdu, static rendering, a language chooser at the site root and no cookies (F04). Libraries such as next-intl solve this but add middleware and configuration the team must learn and upgrade.

## Decision
Use a small in-house layer in `apps/web/i18n`: one JSON file per locale, `{placeholder}` interpolation, `_one` / `_other` plural keys chosen with `Intl.PluralRules`, and `Intl.NumberFormat` for numbers. The locale is a URL segment; the root page stores the chosen locale in browser storage.

## Consequences
- No middleware, no cookies; pages render statically.
- No ICU message syntax or rich-text formatting. If messages need them, switch to next-intl — the JSON files carry over with key renames.
